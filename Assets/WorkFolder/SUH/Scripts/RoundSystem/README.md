# MainScene 라운드 시스템

`Assets/Scenes/MainScene.unity`의 `RoundSystem` 오브젝트에 연결되어 있습니다.
PAP/BK의 기존 스크립트는 수정하지 않고 사용합니다. 현재 로비의 Fusion Shared 모드를 기준으로 합니다.

## 동작

1. 방 생성 시 선택된 첫 맵을 유지합니다. 첫 캐릭터가 생성되면 1라운드를 시작합니다.
2. `TimerAndRoundCanvas`에 네트워크 기준 남은 시간을 표시합니다. 기본 284초(4분 44초)이며 라운드 번호 텍스트는 제거했습니다.
3. 종료 시 모든 클라이언트에서 캐릭터를 비활성화하고 `FinalRankingCanvas`에 상위 3명과 내 순위를 표시합니다.
4. 결과를 10초 표시합니다. 기존 비동기 점수 저장이 마무리될 수 있도록 이때는 캐릭터의 네트워크 상태를 유지합니다.
5. 캐릭터와 별도 생성된 장착 무기를 소유 클라이언트가 정리합니다. 방장이 다음 맵을 선택하고 모든 클라이언트가 같은 프리팹을 로드합니다.
6. 맵 준비 응답을 기다린 후 새 라운드를 시작하고 기존 장비 선택으로 새 캐릭터를 스폰합니다. 로딩 제한 시간(기본 15초)을 넘은 클라이언트는 자신의 맵이 준비된 후 합류합니다.

## Inspector 설정

- `RoundSystem / Round Duration Seconds`: 한 라운드 시간.
- `Result Duration Seconds`: 결과 화면 시간, 최소 10초.
- `MapService / Maps`: 랜덤 순환에 포함할 `MapDefinition` 프리팹 배열. 현재 카탈로그의 맵 3개가 연결되어 있습니다. 비우면 전체 카탈로그를 사용합니다.
- 새 맵은 먼저 로비와 `MapLoader`가 사용하는 `Resources/MapCatalog`에 등록하고 `Maps` 배열에 추가하세요. 미등록 프리팹은 Inspector 검증에서 경고하고 선택에서 제외합니다.
- 후보가 2개 이상이면 직전 맵은 제외합니다. 1개면 해당 맵을 새로 생성합니다.
- `SpawnService`의 프리팹·부위 데이터·장비 컨테이너는 기존 PlayerSpawner와 동일하게 연결되어 있습니다.

순위는 기존 DataStore의 누적 Score/KillCount에서 라운드 시작값을 뺀 값입니다. 저장된 누적 기록을 초기화하지 않습니다. 점수 저장이 비동기이므로 결과 화면 중 저장 완료에 따라 순위가 갱신될 수 있습니다. 네트워크 순위/준비 테이블은 각각 최대 64명입니다.

MapLoader에 공개 재로딩 API가 없어 MapService만 `SendMessage("Load", index)`로 기존 로드 경로를 호출합니다. 이 경로가 갱신하는 `MapLoader.Current`와 `MapLoaded`를 그대로 사용하며, `link.xml`로 빌드 시 해당 메서드 제거를 방지합니다.

## 실행 확인 절차

- 서로 다른 클라이언트 2개에서 방 생성 시 선택한 맵이 같은지 확인.
- 라운드 시간을 10초로 낮춰 플레이 → 순위 10초 → 랜덤 맵 → 자동 재스폰을 3회 반복.
- 죽은 상태에서도 다음 라운드에 체력/장비가 정상 복구되는지 확인.
- 결과 표시 중 신규 접속, 플레이 중 신규 접속, 결과 표시 중 방장 퇴장 확인.
- 후보 1개, 비어 있는 배열, 미등록 맵만 넣은 배열 확인.
- 콘솔의 MissingReference/중복 스폰/무기 잔존 여부 확인.

C# 프로젝트 빌드와 씬 참조 정적 검증을 수행했습니다. 실제 Unity Play Mode의 다중 클라이언트 검증은 별도로 필요합니다.

## 체스판 밸런스 조절

`Scenes/MainScene → RoundSystem → Inspector → Chess Balance (applied next round) → Chess Balance`에서 수정합니다. Play 모드 밖에서 수정해야 저장됩니다. 진행 중 변경은 방장의 다음 라운드 시작 때 적용되고, 적용값은 네트워크로 동기화합니다.

| Inspector 항목 | 기본값 | 의미 |
| --- | --- | --- |
| Cycle Seconds | 44 | 전체 붕괴·복원 반복 주기 |
| First Warning Seconds | 10 | 각 주기 시작부터 첫 예고까지 대기 |
| Batch Interval Seconds | 2 | 다음 묶음의 예고 간격 |
| Tiles Per Batch | 2 | 한 묶음의 타일 수 |
| Max Missing Ratio | 0.3 | 동시에 사라질 수 있는 최대 비율 |
| Warning Seconds | 2 | 흔들리는 예고 시간, 충돌 유지 |
| Fall Seconds | 1.2 | 충돌을 끈 뒤 낙하하는 시간 |
| Restore Seconds | 36 | 주기 시작 기준 순차 복원 시작 |
| Restore Spread Seconds | 6 | 각 타일의 복원 시작을 분산하는 시간 |
| Restore Rise Seconds | 0.8 | 한 타일이 올라와 채워지는 시간 |

현재 81개 중 최대 24개가 사라지고 57개는 남습니다. 첫 실제 낙하는 12초에 시작합니다. 284초 라운드에서 36/80/124/168/212/256초부터 순차 복원을 시작하고, 각각 6.8초 뒤 완료합니다. 총 6회 완료됩니다. 마지막 묶음의 예고·낙하가 복원 전에 끝나도록 신규 예고를 제한합니다. 잘못 입력한 시간은 라운드 시작 시 안전한 범위로 보정합니다.

부모 모델 이름과 관계없이 현재 맵의 `Tile_R숫자_C숫자_Black/White` 구조를 인식합니다. 기존 바닥 박스 2개는 끄고 타일별 충돌을 사용하며, 테두리와 사망 트리거는 유지합니다. DOTween 시퀀스는 네트워크 시간으로 동기화하고 복원·맵 교체 때 정리합니다.

빌드와 타임라인 계산을 검증했습니다. 실제 캐릭터의 이동 속도에 대한 재미·난이도는 플레이 테스트로 추가 조절해야 합니다.

복원 타일은 한 칸씩 약 0.26초 간격으로 3m 아래에서 올라옵니다. 제자리 도착 후 충돌을 켜며, 복원 트윈도 동일한 네트워크 시간으로 진행합니다. 예고 시간과 묶음 선택 간격은 그대로 두고 실제 낙하만 1.8초에서 1.2초로 단축했습니다.

## 스폰 지점 보호

`RoundSystem → Chess Balance → Spawn Protection Radius` 기본값은 3m입니다. `MapDefinition.SpawnPoints`에 등록된 모든 스폰 지점 주변의 수평 원과 겹치는 타일을 낙하 후보에서 제외합니다. 높이는 무시하고 원래 타일 콜라이더의 바닥 면적을 기준으로 판단하므로, 타일 중심이 보호 범위 밖이어도 가장자리가 닿으면 보호합니다. 0으로 설정해도 스폰 지점 바로 아래 타일은 보호합니다.

보호 타일은 예고·낙하 없이 원래 위치와 충돌을 유지합니다. 후보가 부족하면 실제 제거 수를 줄이며, 모든 타일이 보호되면 낙하하지 않습니다. 보호 반경은 다른 밸런스 값과 함께 방장의 라운드 시작 시 네트워크로 동기화됩니다. 스폰 퍼짐 범위를 늘릴 경우 보호 반경도 그보다 넓게 설정하세요. 스폰 지점이 등록되지 않은 경우 기존 스폰 코드와 같이 맵 원점을 기준으로 보호합니다.
